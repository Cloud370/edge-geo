# IP 地理位置查询服务需求文档

## 1. 项目概述
构建一个托管在 Cloudflare 上的高性能 IP 查询服务。系统需具备智能识别客户端的能力：针对浏览器访问返回精美的前端页面，针对命令行工具（如 curl）或脚本访问直接返回 JSON 数据。

## 2. 交互与接口设计 (核心变更)

系统不再强制区分“API 路径”和“页面路径”，而是采用**统一入口、智能分流**的策略。

### 2.1 智能内容协商 (Content Negotiation)
后端 Worker 需检测请求头中的 `User-Agent` 或 `Accept` 字段。
*   **浏览器访问**（UA 包含 Mozilla, Chrome, Safari 等）：返回 **HTML 前端页面**。
*   **非浏览器访问**（UA 为 curl, wget, python, go 等）：直接返回 **纯 JSON 数据**。

### 2.2 接口定义

#### A. 查询当前 IP (简化版)
*   **请求方式**：`GET /`
*   **逻辑**：不带任何参数。
*   **行为**：
    *   **浏览器**：渲染首页，并在显眼位置展示访问者的**当前 IP** 及其地理位置。
    *   **CLI (curl)**：返回访问者当前 IP 的 JSON 详情。

#### B. 查询指定 IP (路径参数)
*   **请求方式**：`GET /<IP_ADDRESS>`
*   **示例**：`GET /1.1.1.1`
*   **行为**：
    *   **浏览器**：渲染首页，搜索框自动填充该 IP，并在结果卡片中展示该 IP 的详情。
    *   **CLI (curl)**：直接返回该 IP 的 JSON 详情。

#### C. 批量查询
*   **请求方式**：`POST /` (直接向根路径 POST)
*   **Body**：JSON 格式，如 `["1.1.1.1", "8.8.8.8"]` 或 `{"ips": [...]}`。
*   **行为**：无论 UA 是什么，始终返回 JSON 数组结果。

## 3. 前端页面需求

### 3.1 视觉与体验
*   **极简大气**：大字号排版，去除冗余元素，类似“IP.SB”或“Vercel”的设计风格。
*   **即时反馈**：进入页面无需点击，立即显示结果。
*   **暗黑模式**：自适应系统外观。

### 3.2 功能细节
*   **搜索框**：位于页面中央，支持输入 IP 回车查询。
*   **快捷复制**：提供一键复制 IP、一键复制 JSON 结果的按钮。
*   **地图预览 (可选)**：如果数据包含经纬度，显示一个静态的极简地图缩略图。

## 4. 后端与数据逻辑

### 4.1 数据处理
*   **数据源**：MaxMind GeoLite2 City。
*   **自动化更新**：GitHub Actions 每周自动拉取、清洗并导入 Cloudflare D1 数据库。
*   **字段精简**：数据库仅存储 `start_ip`, `end_ip`, `country_code`, `city_name`, `latitude`, `longitude`。

### 4.2 性能与缓存
*   **拆分缓存策略**：
    *   针对批量 POST 请求，后端需将 IP 列表拆解，逐个查询 Cache API。
    *   **未命中**的 IP 查询数据库，**命中**的直接复用，最后组装返回。
*   **异步缓存写入**：使用 `ctx.waitUntil` 机制，确保查询响应速度不受写缓存操作影响。
*   **JSON 格式优化**：返回的 JSON 应去除 null 值的字段，保持包体最小。

## 5. 验收标准示例

*   **场景 1 (CLI)**:
    *   输入：终端执行 `curl https://your-domain.com`
    *   输出：`{"ip": "202.x.x.x", "country": "CN", "city": "Beijing"}` (JSON)
*   **场景 2 (浏览器)**:
    *   输入：浏览器地址栏输入 `https://your-domain.com`
    *   输出：加载 HTML 页面，UI 中显示 "202.x.x.x 北京, 中国"。
*   **场景 3 (指定 IP)**:
    *   输入：浏览器访问 `https://your-domain.com/8.8.8.8`
    *   输出：加载 HTML 页面，UI 中显示 "8.8.8.8 美国"。
*   **场景 4 (批量)**:
    *   输入：POST 请求 `["1.1.1.1"]`
    *   输出：JSON 数组。
